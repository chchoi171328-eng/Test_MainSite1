# 가이드 콘텐츠 표준 — 법무법인 명 (SOL & LUNA)

> 이 문서는 홈페이지 「법률정보」에 올라가는 **가이드 글**의 표준이다.
> 신규 스킬(`legal-guide-writer`) 설계의 기준 문서이며, 확정 예시는
> `guide-sample-myeongdo.html`(명도소송 편)이다.
> 상위 기준: `FIELD_MASTER_PLAN.md` (분야 체계·표기 표준은 그쪽이 우선)

---

## 0. 왜 블로그가 아니라 가이드인가

기존 `korean-blog-writer`는 **네이버 블로그용 발행 글**을 위한 스킬이다. 발행일이 붙고,
후킹 제목을 쓰고, 주기적으로 쌓는 형식이다. 그 용도는 계속 유지한다.

홈페이지 「법률정보」는 다른 물건이다.

| | 네이버 블로그 (기존 스킬) | 홈페이지 가이드 (이 표준) |
|---|---|---|
| 축 | 시간축 — 최신순으로 흐름 | 주제축 — 분야별로 쌓임 |
| 목적 | 플랫폼 지수·노출 | 검색 착지 자산·신뢰 |
| 수량 | 다작 | 소수 정예, 갱신으로 관리 |
| 날짜 | 발행일 | **검토일** |
| 제목 | 후킹 허용 | 상황·과제형, 시의성 배제 |
| 중복 | — | **같은 주제 반복 발행 금지** |

핵심 원칙 두 가지:

1. **한 주제 = 한 문서.** 같은 검색어를 노리는 글을 여러 편 만들지 않는다. 보강이
   필요하면 새 글이 아니라 **기존 문서를 갱신**한다. (동일 주제 분산은 검색에서
   서로의 순위를 깎는다.)
2. **가이드는 세부 페이지의 한 문장을 한 편으로 펼친 것.** 업무 분야 세부 페이지가
   기둥이고 가이드가 가지다. 톤·문법은 세부 페이지와 같은 혈통이어야 한다.

네이버와 홈페이지에 **같은 글을 그대로 올리지 않는다.** 조사는 재활용하되, 네이버는
짧고 사례 중심의 대화체, 홈페이지 가이드는 완결된 구조로 다르게 쓴다.

## 1. 골격 (섹션 순서)

```
[헤더]  분야 breadcrumb / 제목(H1) / 메타(분야 · 작성자 · 검토일)
[히어로 이미지]                                    필수
[요약 박스]                                        필수
[도입]  2~3문단, 첫 200자에 메인 키워드            필수
[목차]  H2 앵커 링크만                             H2 5개 이상이면 필수
[본문]  H2 5~8개 (아래 2절)                        필수
  └ 본문 이미지 1~2장, 표, 절차 도식, callout을 필요한 위치에
[기한 박스]                                        해당 기한이 있으면 필수
[자주 묻는 질문]  4~6문항                          필수
[법률 정보 안내]  고정 문구                        필수
[함께 보면 좋은 자료]  분야 내 링크 3~4개          필수
[정직하게 말씀드리는 법률 상담]  브랜드 앵커 CTA   필수
[푸터 메타]  작성자 / 검토일                       필수
```

**두지 않는 것:**
- 「이런 상황이라면」 확인 섹션 — 세부 페이지의 문법이다. 가이드는 제목과 검색어로
  이미 상황이 특정되어 들어오므로 불필요하다.
- 다른 주제로 보내는 분기 라인 — 같은 이유. 관련 주제는 마지막 「함께 보면 좋은
  자료」에서 다룬다.
- 「직접 할 수 있는 것 / 변호사가 필요한 지점」 표준 섹션 — **표준화하지 않는다.**
  대부분의 분야는 실제로 혼자 할 수 있는 것이 별로 없고, 나홀로 소송을 권유하는
  것은 이 사무소의 입장이 아니다. 셀프 가능한 절차가 실제로 있고 그것을 숨기는
  것이 부정직해지는 경우에만(예: 임차권등기명령) 본문에 사실로 한 줄 적는다.

## 2. 본문 H2 구성 원칙

- **각 H2가 하나의 하위 검색 질의에 대응**하도록 쪼갠다.
  (예: "점유이전금지가처분이란", "명도소송 비용", "강제집행 절차")
- 절차형 주제는 **시간 순서**로, 쟁점형 주제는 **판단 순서**로 배열한다.
- 마지막에서 두 번째 H2는 가능하면 **「자주 하는 실수」 또는 「미리 정리해 둘 것」**
  성격으로 둔다 — 검색 유입자에게 실질 가치가 크고, 경쟁 콘텐츠에 잘 없다.
- 각 H2 아래 문단은 **3~4문장** 단위로 끊는다 (모바일 가독성).

## 3. 컴포넌트 사양

### 3-1. 요약 박스 (필수)
- 위치: 히어로 이미지 직후, 도입보다 앞
- 4~6개 항목, 각 1~2문장. 결론만 적는다. 서론·배경 금지
- 핵심 어구는 굵게. 이 박스만 읽어도 답이 끝나야 한다
- 이유: (1) 답부터 말하는 사이트 문법 (2) AI 검색·구글 AI 요약이 인용하는 지점

### 3-2. 목차 (H2 5개 이상이면 필수)
- H2만 나열(H3 제외), FAQ·안내·CTA는 제외
- 앵커 ID는 영문 slug(`#deposit-return`) — 한글 앵커 금지
- 렌더러의 자동 헤딩 ID 생성 방식과 일치해야 하므로 구현 시 확인 항목

### 3-3. 표
- 비교·기준·비용·기간·서류 목록은 서술 대신 표로
- 법령 근거가 있으면 **근거 열**을 둔다 (조문명 표기 — 독자가 직접 확인 가능하게)

### 3-4. 절차 도식 (HTML 컴포넌트, 이미지 아님)
- 번호 + 단계명 + 한 줄 설명. 필요 시 소요 기간 표기
- 이미지로 만들지 않는다 — 텍스트여야 검색에 잡히고, 수정이 문장 고치듯 된다

### 3-5. 기한 박스 (해당 기한이 있으면 필수)
- 다크 배경. 정의형 목록(항목 — 기한)
- 마지막 한 줄은 행동 유도가 아니라 **확인 권유** ("~부터 확인해 보세요")
- 사이트 전역의 기한 문법(세부 페이지 8종)과 같은 계열

### 3-6. Callout (경고·주의)
- 노란 계열 박스. 하지 말아야 할 것, 오해하기 쉬운 것 한 건에 하나
- 죄명을 단정하지 않는다 — "다른 법적 문제를 발생시킬 수 있습니다" 수준으로

### 3-7. FAQ (4~6문항)
- 본문에서 다루지 못한 **롱테일 질문**을 담는다. 본문 요약 반복 금지
- 해당 분야 세부 페이지의 FAQ와 중복되지 않게
- 마지막 문항은 대개 "상가와 주택은 다른가요" 같은 **경계 질문**이 좋다

### 3-8. 법률 정보 안내 (고정 문구, 그대로 사용)
> 이 글은 일반적인 법률 정보 제공을 목적으로 하며, 개별 사안에 대한 법률 자문이
> 아닙니다. 법령은 수시로 개정되며, 구체적인 결론은 개별 사건의 사실관계에 따라
> 달라질 수 있습니다. 본인의 상황에 대한 정확한 판단이 필요하시면 변호사와
> 상담하시기 바랍니다.

### 3-9. 함께 보면 좋은 자료
- ① 해당 분야 세부 페이지(필수) ② 같은 분야 가이드 2~3편 ③ 관련 스마트 도구
- 같은 분야끼리 상호 링크해 **토픽 클러스터**를 만든다

### 3-10. 브랜드 앵커 CTA (고정 블록, {상황 한 줄}만 교체)
> **정직하게 말씀드리는 법률 상담**
> 법무법인 명은 모든 사건을 맡지는 않습니다. 승산 없는 소송은 권하지 않습니다.
> {주제에 맞는 상황 한 줄}, {그 주제에서 상담이 실제로 해줄 수 있는 것}부터
> 정직하게 말씀드리겠습니다. 사무소는 경기도 평택시에 있습니다.
> [전화] [온라인 상담 신청]

### 3-11. 푸터 메타
```
작성 · 최철호 변호사 (법무법인 명, 대한변호사협회 등록 형사법·민사법 전문변호사)
검토 · {YYYY}년 {M}월 기준으로 내용을 확인했습니다. 법령·판례 변경 시 갱신합니다.
```
- 전문분야 표기는 마스터 플랜 §2-1의 문구를 그대로 사용
- **발행일을 표기하지 않는다.** 상단 메타·푸터 모두 검토일만 쓴다

## 4. 문체·톤 규칙

기존 `korean-blog-writer`의 규칙을 승계한다. 특히 다음은 **그대로 유지**:

- **정보 우선, 광고 최소화** — 본문에 수임 유도·자기 홍보·공포 마케팅 금지.
  광고성 내용은 말미 CTA 블록 하나로만.
- **판례 인용 금지 (하드 룰)** — "판례는", "대법원은 ~라고 판시" 류 표현과
  사건번호 금지. 근거는 **법령 조문**으로만 서술. 판례 없이 논지가 성립하지 않는
  예외 상황에서는 **작성을 중단하고 사용자 검토·승인**을 받는다.
- **법률 용어는 첫 등장 시 일상어로 풀이** — 별도 스타일(작은 회색 문장)로 처리.
  예: "명도(明渡)는 건물을 비워서 넘겨주는 것을 말합니다. 법률상 정식 용어는
  '인도'이고 법원 서류에는 건물인도청구로 적힙니다."
- **금액·기간·기수는 구체적으로**, 다만 확정할 수 없는 것은 확정하지 않는다
  ("사건에 따라 다릅니다"를 쓰되, 무엇에 따라 다른지는 밝힌다).
- **2인칭 상황 제시**로 독자에게 직접 말 걸기.
- 확정적 결과 보장 표현 금지("반드시 이깁니다", "무조건").

가이드 고유 규칙 추가:

- **시의성 표현 금지** — "최근", "요즘", "올해 들어", "얼마 전 개정된" 같은 표현을
  쓰지 않는다. 날짜 없는 문서이므로 시간이 지나면 거짓이 된다. 시점이 꼭 필요하면
  "2026년 7월 기준"처럼 명시한다.
- **깊이의 상한** — 절차·기준·요건은 끝까지 알려준다. 다만 **"내 사건에 어떻게
  적용되는가"의 판단은 상담의 몫**으로 남긴다. 정보를 감추고 티저를 던지는 것은
  금지하되, 사건별 결론을 단정하지도 않는다.

## 5. 제목 · 메타 · URL

### 제목 — 2종 생성 (블로그 스킬과 같은 체계, 성격만 다름)

**listingTitle (목록·링크용 — 짧게)**
- 주제명 그대로, 8~18자. 예: `명도소송 절차`, `점유이전금지가처분`
- 가이드 목록은 목차처럼 훑는 화면이므로 한 줄에 잡혀야 한다
- 세부 페이지 §9 링크, 관련 자료 목록에도 이 제목을 쓴다
- **후킹 금지** — 블로그의 listingTitle(호기심·숫자·질문형)과 달리, 가이드는
  주제명이 곧 목록 제목이다

**seoTitle (H1 + title 태그 — 길게)**
- 형식: `{검색어} — {독자의 질문에 답하는 구}`
  - 예: `명도소송 절차 — 나가지 않는 임차인, 법으로 내보내는 순서`
- 메인 키워드를 앞쪽에 배치. title 태그에는 `| 법무법인 명` 브랜드 접미
- 시의성·연도 표기 금지. 과장·클릭베이트 금지(변협 광고규정)

### metaDescription
- 80자 이내, 메인 키워드 포함, 그 글이 답하는 범위를 요약

### URL
```
/guides/{분야키}/{주제-slug}
예: /guides/real-estate/myeongdo-procedure
```
- 날짜·번호를 URL에 넣지 않는다
- 분야키는 아래 6절의 값만 사용

| 분야키 | 표시명 | 세부 페이지 |

| civil | 민사 소송 | /practice/civil |

  (3) 관련 자료 클러스터가 모두 처리된다

## 7. 이미지

기존 스킬의 **하드 규칙 3종과 검증 게이트를 그대로 승계**한다.

1. 등장인물 전원 한국인 (프롬프트에 인물마다 Korean 명시)
2. 얼굴 비노출 (뒷모습·크롭·실루엣·아웃포커스만)
3. 텍스트 없음 (no text, no letters, no signage, no Korean characters, no Hangul)
   — 인물이 필요 없는 주제는 **사물·공간 이미지를 우선**한다 (1·2가 자동 충족)

가이드 고유 사양:

- 수량: **히어로 1장 + 본문 1~2장** (블로그보다 적게)
- 비율 16:9, 모델 GPT Image 2(`gpt-2`), 해상도 1k~2k
- **캡션에 정보를 싣는다.** 장식이 아니라 읽을거리가 되도록, 그 위치의 핵심 사실을
  한 문장으로 (예: "짐이 남아 있다면 점유는 유지되고 있는 것으로 다루어집니다")
- alt 텍스트에 주제 키워드를 자연스럽게 포함
- **절차·구조를 나타내는 것은 이미지로 만들지 않는다** — HTML 도식(3-4)을 쓴다
- 검증 게이트: 생성된 이미지를 열어(view) 얼굴·텍스트·인물 국적을 확인. 실패 시
  프롬프트 수정 후 재생성(이미지당 최대 2회). 검증 없이 산출물에 포함 금지

## 8. 분량

| 구분 | H2 개수 | 공백 제외 글자 수 | 이미지 | FAQ |
|---|---|---|---|---|
| 표준 가이드 | 5~8개 | **5,000~6,500자** | 2~3장 | 4~6문항 |
| 소형 가이드 | 3~4개 | 3,000~4,000자 | 1~2장 | 3~4문항 |

- 기본은 표준 가이드. 소형은 주제가 좁고 명확할 때만
- 글자 수는 고정 블록(안내·CTA) 포함 기준. 작성 후 실측해 범위를 맞춘다

---

## 9. 검토일과 갱신 관리

- 모든 가이드는 `reviewedAt`(YYYY-MM)을 갖는다. 발행일은 두지 않는다
- 표기: 상단 메타 + 푸터 두 곳에 "{YYYY}년 {M}월 기준 확인"
- **반기 1회** 전체 가이드를 훑어 법령·수치·절차 변경을 확인하고 검토일을 갱신한다
- 법령 개정·중요 판례 변경이 있으면 해당 가이드를 즉시 갱신한다.
  **새 글을 쓰지 않는다** — 기존 문서 갱신이 검색에서도 더 유리하다
- 날짜가 의미를 갖는 내용(법 개정 소식, 사무소 소식)은 가이드가 아니라
  **별도 「소식」 게시판**에 발행일과 함께 올린다

## 10. frontmatter 스키마 (MDX 파일 기반)

가이드는 DB가 아니라 저장소 파일로 관리한다. 파일 1개 = 가이드 1편.

```yaml
---
listingTitle: "명도소송 절차"          # 목록·링크용 짧은 제목
title: "명도소송 절차 — 나가지 않는 임차인, 법으로 내보내는 순서"   # H1·title 태그 (seoTitle)
slug: "myeongdo-procedure"
field: "real-estate"          # 6절의 분야키
summary: "임차인이 나가지 않을 때의 절차를 계약 해지부터 강제집행까지 정리했습니다."
metaDescription: "명도소송 절차를 계약 해지, 점유이전금지가처분, 소송, 강제집행 순서로 정리했습니다."
keywords: ["명도소송", "점유이전금지가처분", "건물인도청구"]
reviewedAt: "2026-07"
author: "최철호"
thumbnail: "./thumbnail.jpg"
related: ["jeomyu-gacheobun", "kwolligeum-banghae"]   # 같은 분야 가이드 slug
tools: ["court-fee-calculator"]                        # 연결할 스마트 도구
---
```

- 목록 페이지·분야 필터·세부 페이지 §9 연결은 이 frontmatter에서 **빌드 시 자동 생성**
- 본문은 마크다운 + 공통 컴포넌트(요약박스·기한박스·절차도식·callout·FAQ)
- 컴포넌트는 레이아웃 하나에서 관리 — 스타일 변경 시 전 가이드에 일괄 반영

---

## 11. 산출물 패키지

```
output/{field}/{slug}/
├── index.mdx        ← frontmatter + 본문
├── thumbnail.jpg    ← 16:9 히어로
├── image-1.jpg
└── image-2.jpg      (필요 시)
```

전달 시 보고 항목: 제목 / 분야키 / slug / 글자 수 / 이미지 검증 결과 /
판례 인용 여부(있으면 승인 대기 표시).

## 12. 품질 체크리스트 (전달 전 자체 점검)

- [ ] 같은 주제의 기존 가이드가 없는가 (있으면 신규 작성이 아니라 **갱신**)
- [ ] 분야키가 8분야 중 하나로 정확히 지정되었는가
- [ ] 제목 2종이 있는가 — listingTitle은 짧은 주제명(후킹 아님), seoTitle은 검색어 앞배치
- [ ] 요약 박스만 읽어도 답이 끝나는가
- [ ] H2가 각각 별개의 검색 질의에 대응하는가
- [ ] 목차 앵커가 영문 slug이고 헤딩 ID와 일치하는가
- [ ] 「이런 상황이라면」·분기 라인·셀프 안내 표준 섹션이 들어가지 않았는가
- [ ] 판례 언급·사건번호가 없는가 (있다면 승인받았는가)
- [ ] 법령 조문으로 근거를 밝혔는가
- [ ] 법률 용어를 첫 등장 시 풀이했는가
- [ ] 시의성 표현("최근", "요즘")이 없는가
- [ ] 본문에 수임 유도·자기 홍보 문장이 없는가 (광고는 말미 CTA 하나뿐인가)
- [ ] 금액 표기가 마스터 플랜 표준인가 ("만 원" 띄어쓰기 / 하한은 "부터")
- [ ] 기한 정보가 있는 주제인데 기한 박스를 누락하지 않았는가
- [ ] 이미지 전부 검증 게이트 통과(전원 한국인·얼굴 비노출·텍스트 없음)
- [ ] 캡션이 정보를 담고 있는가
- [ ] 관련 자료에 해당 분야 세부 페이지가 포함되었는가
- [ ] 법률 정보 안내·브랜드 앵커 CTA·푸터 메타가 모두 있는가
- [ ] 발행일이 아니라 검토일로 표기되었는가
- [ ] 글자 수가 범위 내인가 (실측할 것)

## 13. 스킬 설계 메모 (`legal-guide-writer`)

- **기존 `korean-blog-writer`를 수정하지 않는다.** 그 스킬은 네이버 블로그용으로
  계속 쓴다. 신규 스킬로 분리한다.
- 승계할 references: 이미지 프롬프트 가이드(하드 규칙·검증 절차), 판례 인용 금지
  규칙, 문체 규칙, 고정 블록 문구
- 새로 필요한 references:
  - `guide-structure.md` — 본 문서 1~4절 (골격·컴포넌트 사양)
  - `field-keys.md` — 6절 분야키와 세부 페이지 매핑
  - `mdx-template.md` — 10~11절 frontmatter·패키지 구조
- 워크플로 차이: 제목 2종 생성은 **유지**하되 listingTitle의 성격이 바뀐다
  (블로그: 후킹형 → 가이드: 짧은 주제명). 그리고 **"기존 가이드 중복 확인"** 단계가
  맨 앞에 추가된다 (같은 주제가 있으면 신규 작성 대신 갱신 제안).
