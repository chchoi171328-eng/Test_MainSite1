# 건설·공사대금 가이드 작성·발행 지시서 (Claude Code용)

> 전제: `GUIDE_BOARD_BRIEF.md`의 게시판 구조(MDX 파일 기반, /content/guides/)가
> 구현되어 있어야 한다. 미구현이면 그 작업을 먼저 한다.
> 글 작성은 **legal-guide-writer 스킬**을 사용한다 (설치되어 있지 않으면 사용자에게
> `legal-guide-writer.skill` 설치를 요청). 콘텐츠 표준·워크플로·하드 룰은 전부
> 스킬과 `GUIDE_CONTENT_STANDARD.md`를 따르고, 이 지시서는 **무엇을 어떤 순서로
> 쓰는지**만 정한다.

## 0. 공통 규칙

- field는 전부 `construction`. 산출물은 `/content/guides/construction/{slug}/`.
- **발행 게이트**: 각 편은 ①스킬로 초안 생성 → ②"확인 필요" 법률 내용 목록을
  사용자(변호사)에게 보고 → ③승인·교정 반영 → ④커밋·배포 순서를 지킨다.
  **변호사 검토 없이 발행하지 않는다** (변호사 명의로 나가는 법률 정보다).
- 판례 인용 금지 룰은 스킬 그대로. 판례 없이 논지가 안 서는 지점은 승인 게이트로.
- 이미지: Artlist MCP가 이 환경에 연결되어 있으면 스킬 5단계대로 생성. 연결되어
  있지 않으면 **텍스트를 먼저 완성**하고 이미지 자리는
  `<!-- TODO: image — {프롬프트 요지} -->`로 남긴 뒤 사용자에게 보고한다
  (이미지는 claude.ai 세션에서 별도 생성 가능).
- 한 세션에서 한 번에 여러 편을 쓰지 말 것 — **1편 완성·검토·발행 후 다음 편**.
  품질과 검토 부담 관리를 위한 규칙이다.

## 2. 클러스터 링크 (frontmatter `related` 지정)

- 1 ↔ 2 상호 링크 필수 — 각자의 「함께 보면 좋은 자료」에서 상대편을
  "반대 입장이라면" 성격으로 가리킨다
- 3·4·5의 related: ["payment-claim"] (+ 서로)
- 6·7: ["payment-claim", "defending-payment-claim"]
- 8: ["defending-payment-claim", "payment-claim"] / 9: ["payment-claim"]
- 10: ["payment-claim", "statute-of-limitations"] / 11: ["payment-claim"]
- 아직 발행 전인 slug는 related에 미리 넣지 말고, 해당 편 발행 시 **양쪽을 함께
  갱신**한다 (깨진 링크 금지)
- 모든 편의 관련 자료 첫 항목은 자동으로 /practice/construction (구조가 처리)
